# Simulator compatibility matrix

- **Simulator version:** `kubernetes-1.37-subset-1`
- **Target:** a documented subset of Kubernetes v1.37 (v1.37.1 was the latest patch on 2026-10-22)
- **Rule:** anything not listed here as *supported* or *partial* fails with `UNSUPPORTED` and a message saying what to do instead. The simulator never silently ignores input.

Support levels:

| Level | Meaning |
| --- | --- |
| **Supported** | Behaves like Kubernetes v1.37 for the cases listed; differences are documented below |
| **Partial** | Works for the listed subset; other flags/fields return `UNSUPPORTED` |
| **Concept only** | Accepted and stored, but the real-world effect (traffic, storage, isolation) does not exist; the UI and lesson text say so |
| **Not supported** | Returns `UNSUPPORTED` |

## 1. Resource kinds

| Kind | apiVersion | Scope | Level | Notes |
| --- | --- | --- | --- | --- |
| Namespace | `v1` | Cluster | Supported | `default`, `kube-system`, `kube-public`, `kube-node-lease` are seeded and cannot be deleted. Deleting a namespace deletes its contents (no visible `Terminating` phase). |
| Node | `v1` | Cluster | Partial | Seeded by fixtures; learners cannot create or delete them. `kubectl label`/`annotate` work. Capacity, allocatable, labels, taints and `Ready` condition come from the fixture. `cordon`, `drain`, `taint` are not supported. |
| Pod | `v1` | Namespaced | Partial | Containers: `name`, `image`, `command`, `args`, `env` (`value`, `valueFrom.configMapKeyRef`, `valueFrom.secretKeyRef`), `envFrom` (`configMapRef`, `secretRef`), `ports`, `resources.requests/limits` (cpu, memory). Pod: `nodeSelector`, `tolerations`, `restartPolicy` (`Always` only), `labels`, `annotations`. Init containers, volumes, probes, affinity, security contexts: not supported. Spec is immutable after creation except labels/annotations (matches Kubernetes for these fields). |
| Deployment | `apps/v1` | Namespaced | Partial | `replicas`, `selector` (immutable), `template`, `strategy.type` (`RollingUpdate` with `maxSurge`/`maxUnavailable`, or `Recreate`), `revisionHistoryLimit`. `paused`, `progressDeadlineSeconds`, `minReadySeconds`: not supported. |
| ReplicaSet | `apps/v1` | Namespaced | Partial | Normally created by Deployments; can be created directly. Same template subset as Pod. |
| Service | `v1` | Namespaced | Partial | `ClusterIP` and `NodePort` supported; `LoadBalancer` is *concept only* (EXTERNAL-IP stays `<pending>`, as on a cluster with no load-balancer controller). `ExternalName`, headless (`clusterIP: None`), session affinity: not supported. No traffic is routed anywhere. |
| EndpointSlice | `discovery.k8s.io/v1` | Namespaced | Supported (read-only) | Managed by the simulated EndpointSlice controller for each Service with a selector; one slice per Service, labelled `kubernetes.io/service-name`. Learners can read but not create/edit them. |
| Endpoints | `v1` | Namespaced | Partial (read-only) | Derived view of the EndpointSlice for `kubectl get endpoints`. Prints the same deprecation warning as kubectl v1.33+ and recommends `endpointslices`. |
| ConfigMap | `v1` | Namespaced | Supported | `data` only (no `binaryData`, no `immutable`). 64 KiB per object in the simulator (Kubernetes allows 1 MiB). |
| Secret | `v1` | Namespaced | Partial | Type `Opaque` only. `data` (base64) and `stringData` on input. **Training values only:** the UI warns learners never to paste real credentials, and Secret values are excluded from logs, telemetry and transcript exports. |
| Event | `v1` | Namespaced | Supported (read-only) | Generated by the simulator; learners cannot create them. Shown by `get events` and in `describe`. |
| Everything else (StatefulSet, DaemonSet, Job, CronJob, Ingress, Gateway, PV/PVC, StorageClass, ServiceAccount, Role/RoleBinding, NetworkPolicy, HPA, ResourceQuota, LimitRange, PodDisruptionBudget, CRDs, …) | — | — | Not supported | `UNSUPPORTED: <kind> is not part of the KubeDojo simulator yet.` |

Object metadata supported on all kinds: `name`, `generateName` (Pods/ReplicaSets via controllers only), `namespace`, `uid`, `labels`, `annotations`, `ownerReferences`, `resourceVersion`, `generation`, `creationTimestamp`. `finalizers`, `managedFields`: not supported. Every object returned by `-o yaml/json` carries the annotation `kubedojo.dev/simulated: "true"`.

Name validation matches Kubernetes: DNS-1123 subdomain for most kinds, DNS-1123 label for Namespace and Service; label keys/values per Kubernetes rules.

## 2. Simulated behaviors

| Behavior | What happens in the simulator | Differs from real Kubernetes |
| --- | --- | --- |
| **Reconciliation** | After each mutating command, controllers run in a fixed order to a fixed point ([ADR-0006](../adr/0006-deterministic-reconciliation.md)). | Real clusters converge asynchronously over seconds. |
| **Simulated time** | Logical clock; +10 s per mutating command; reads don't advance it. `AGE` uses it. | Real clocks keep moving while you read. |
| **Deployment rollouts** | Template change → new ReplicaSet (`pod-template-hash` from a hash of the template) → rolling update honoring `maxSurge`/`maxUnavailable`, recorded as events. `deployment.kubernetes.io/revision` annotation maintained; `rollout history` and `rollout undo [--to-revision]` supported. | Completes within one command. |
| **Scheduler** | Filters Nodes in kube-scheduler's plugin order: `Ready` condition, `unschedulable`, `NoSchedule`/`NoExecute` taints vs. tolerations, `nodeSelector`, then CPU/memory requests vs. allocatable minus already-requested and Pod count vs. allocatable `pods`. Scores by lowest requested-CPU fraction, ties by node name. Failure → Pod stays `Pending` with a `FailedScheduling` event whose message uses kube-scheduler's format, reasons sorted (e.g. `0/3 nodes are available: 1 node(s) had untolerated taint {node-role.kubernetes.io/control-plane: }, 2 Insufficient cpu.`). | No affinity, spreading, preemption or priority, so the message has no `preemption:` suffix. |
| **Image catalog** | Each image reference resolves against a catalog: built-in entries (`nginx:1.25`–`1.27`, `nginx:latest`, `busybox:1.36`, `redis:7`, `httpd:2.4`, `kubedojo/demo-api:1.0`, `kubedojo/demo-api:2.0`, …) plus entries a fixture adds. Unknown image → `ErrImagePull`, then `ImagePullBackOff`, with `Failed`/`BackOff` events. | No registry is contacted; "unknown" means "not in the catalog". |
| **Container behavior profiles** | Each catalog image has a profile: `run` (Running, Ready, fixed log lines) or `crash` (exits with code N, optionally only when a required env var is missing). Crashing containers enter `CrashLoopBackOff`; `restartCount` follows kubelet backoff on simulated time. `logs --previous` shows the last crash output. | Nothing actually runs. Readiness is immediate (no probes). |
| **Config references** | `env.valueFrom` / `envFrom` referencing a missing ConfigMap/Secret or key → container `CreateContainerConfigError` with an event. Creating the referenced object fixes the Pod on the next reconcile. | Matches kubelet behavior; values are never injected anywhere. |
| **IP allocation** | Pod IPs from `10.244.<node-index>.0/24`; ClusterIPs from `10.96.0.0/16`; NodePorts from 30000–32767. All from the session's seeded generator. | No networking exists. |
| **EndpointSlices** | Ready Pods matching a Service's selector become endpoints with their IP and target port. | Topology hints and terminating endpoints not modelled. |
| **Garbage collection** | Deleting an owner deletes dependents (`ownerReferences`, foreground semantics, immediate). `--cascade=orphan` supported. | Immediate. |
| **kubeconfig** | Each lab has one simulated kubeconfig: cluster `kubedojo`, user `learner`, context `kubedojo`. Current namespace defaults to `default` and changes with `config set-context --current --namespace`. Stored on the session. | No credentials or real server. |
| **Logs** | Each catalog profile defines log lines; templated with Pod name/IP. Prefixed in the UI with a "simulated" marker. | Fixed content. |
| **API defaulting** | Like the API server, input gets defaults: Pod `restartPolicy: Always`, container port `protocol: TCP`, Deployment/ReplicaSet `replicas: 1`, Deployment `strategy` RollingUpdate 25%/25% and `revisionHistoryLimit: 10`, Service `type: ClusterIP`, port `protocol: TCP` and `targetPort` = `port`, Secret `type: Opaque`. | Only these defaults. |
| **Reset** | Reloads the lab from its challenge version's fixture with the same seed, so names, UIDs and IPs match the first start. `resourceVersion`s keep increasing across the reset, earlier events are dropped and command history is kept. | No equivalent; recreating a real cluster gives new names. |
| **Apply** | `kubectl apply` stores `kubectl.kubernetes.io/last-applied-configuration` and performs a three-way merge on the supported field subset. | Client-side apply only; server-side apply not supported. |

## 3. Commands

All commands start with `kubectl` (the alias `k` is accepted). Global flags: `-n/--namespace`, `-A/--all-namespaces` (where kubectl allows it), `-h/--help`. Anything else global (`--context`, `--kubeconfig`, `--server`, `--token`, `-v`) returns `UNSUPPORTED`.

**Rejected before parsing** (nothing executes): outside single quotes, `;`, `&&`, `||`, `|`, `&`, `>`, `>>`, `<`, `$(`, `$VAR`/`${VAR}`, backticks and bare `(`/`)` (`UNSUPPORTED_COMMAND`); newlines (multi-line input); control characters, invalid UTF-8, input over 16 KiB and more than 64 words (`VALIDATION_FAILED`); any first word other than `kubectl`/`k`/`clear`/`help` (`UNSUPPORTED_COMMAND`, exit 127). The tokenizer (`internal/kubectl/tokenize.go`) supports single quotes (literal), double quotes (with `\"` and `\\`) and backslash escapes only, and never expands anything. Inside double quotes, `$` and backticks are still rejected because a shell would expand them there.

Failed commands are terminal output, not API errors: `POST /labs/{id}/commands` answers `200` with the exit code, stderr and an `errorCode` (`UNSUPPORTED_COMMAND`, `VALIDATION_FAILED`, `NOT_FOUND`). Each command runs at most once per client `requestId`; a retry returns the stored result. Read commands never change state, the clock or the lab version (golden tests assert this for every command). Command history stores output with Secret `data` values replaced by `<redacted>`; the learner's own terminal shows them.

### Read commands (Part 10)

| Command | Level | Supported options |
| --- | --- | --- |
| `get <type>[,<type>…] [name…]` | Supported | `-o wide\|yaml\|json\|name`, `-l/--selector` (equality and set-based), `--show-labels`, `-n`, `-A`, `--no-headers`, `--sort-by` (metadata.name, metadata.creationTimestamp only). Types: all kinds in §1, plus short names (`po`, `deploy`, `rs`, `svc`, `ns`, `no`, `cm`, `ep`, `ev`) and `all` (= pods, services, deployments, replicasets). `-w/--watch`: not supported (see ADR-0006). `-o jsonpath/custom-columns/go-template`: not supported. |
| `describe <type> <name>` / `describe <type> -l …` | Supported | Kinds in §1. Includes Events section from simulated events. Like kubectl, a name that matches no object exactly describes every object whose name starts with it. Secret values are never printed (sizes only). |
| `logs <pod> [-c container]` | Partial | `pod/<name>`, `deployment/<name>`, `replicaset/<name>` (first Pod, with kubectl's `Found N pods` note), `-c`, `--previous`, `--tail=N`. Containers that never started return kubectl's `waiting to start` error. `-f/--follow`, `--timestamps`, `--all-containers`: not supported. Output is from the image's behavior profile. |
| `get events` / `events` | Supported | `--for <type>/<name>`, `--types Warning,Normal`, `-n`, `-A`. Sorted by simulated time. |
| `explain <type>[.<field>…]` | Partial | Documented fields of supported kinds only; unsupported fields say so. `--recursive` supported. |
| `api-resources` | Supported | `--namespaced=true\|false`, `-o wide\|name`. Lists only simulated kinds, with a footer noting the cluster is simulated. |
| `cluster-info` | Supported | Prints simulated control-plane URLs (`https://kubedojo.sim:6443`). |
| `version` | Supported | `Client Version: v1.37.1`, `Server Version: v1.37.1 (simulated)`. `-o yaml/json`. |
| `config view` / `get-contexts` / `current-context` | Supported | `--minify` for view. |
| `rollout status` / `rollout history` | Supported | `--revision=N` for history. Because the cluster is always reconciled, a rollout that can't finish prints kubectl's `Waiting for deployment …` line, a hint about why, and exits 1 instead of waiting forever. |
| `help`, `<command> --help` | Supported | Lists only supported commands and flags, with a link to the support matrix. |

### Mutating commands (Parts 11–13; listed here so lessons can rely on them)

| Command | Level | Supported options |
| --- | --- | --- |
| `run <name> --image=<img>` | Partial | `--labels`, `--env`, `--port`, `--restart=Always`, `--dry-run=client -o yaml` (prints, doesn't create). `--rm`, `-it`, `--command --`: not supported. |
| `create deployment <name> --image=<img>` | Supported | `--replicas`, `--port`, `--dry-run=client -o yaml`. |
| `create namespace\|ns <name>` | Supported | |
| `create configmap <name>` | Supported | `--from-literal=K=V` (repeatable). `--from-file`: supported for virtual files in the lab editor only. |
| `create secret generic <name>` | Partial | `--from-literal`. Opaque only. Training values only. |
| `create service clusterip\|nodeport <name>` | Supported | `--tcp=port:targetPort`, `--node-port` (NodePort). |
| `create -f <file>` / `apply -f <file>` | Partial | Virtual files from the lab editor only (paths like `manifests/web.yaml`), multi-document YAML, kinds in §1. URLs, directories, `-k` (kustomize), server-side apply: not supported. |
| `delete <type> <name…>` / `delete -f <file>` | Supported | `-l`, `--all`, `--cascade=background\|orphan`. Seeded namespaces and Nodes refuse deletion. |
| `expose deployment\|pod\|service <name>` | Supported | `--port`, `--target-port`, `--type=ClusterIP\|NodePort`, `--name`, `--selector`. |
| `scale deployment\|replicaset <name> --replicas=N` | Supported | `--current-replicas`. |
| `set image deployment/<name> <container>=<img>` | Supported | |
| `set env deployment/<name> K=V` | Partial | `K=V`, `K-` (remove), `--from=configmap/<name>`. |
| `rollout undo deployment/<name>` | Supported | `--to-revision`. |
| `rollout restart deployment/<name>` | Supported | Sets `kubectl.kubernetes.io/restartedAt` from simulated time. |
| `label` / `annotate` `<type> <name> k=v…` | Supported | `k-` removal, `--overwrite`, `-l`, `--all`. |
| `config set-context --current --namespace=<ns>` | Partial | Only `--current --namespace`. |
| `edit` | Not supported | Message points to the lab's YAML editor + `apply`. |
| `patch` | Not supported (V1) | Message points to `apply` or `set`. |
| `exec`, `attach`, `cp`, `port-forward`, `proxy`, `debug`, `top`, `auth`, `certificate`, `cordon`, `drain`, `taint`, `wait`, `diff`, `replace`, `autoscale`, `plugin`, `kustomize` | Not supported | Each has a specific message; for `exec`/`port-forward` it explains no containers run. |

Non-kubectl inputs: `clear` clears the terminal (client-side); `help` prints supported commands. Every other program name (`sh`, `bash`, `curl`, `helm`, `docker`, `cat`, …) returns `UNSUPPORTED_COMMAND: Only kubectl commands are available in the simulator.`

## 4. Output formats

| Format | Fidelity |
| --- | --- |
| Tables | Same column names and order as kubectl v1.37 for each supported kind, including `-o wide` columns. Column widths computed like kubectl's tabwriter (3-space padding). |
| `-o yaml` / `-o json` | Field order follows kubectl's (apiVersion, kind, metadata, spec, status). Includes the `kubedojo.dev/simulated` annotation. `managedFields` omitted. |
| `-o name` | `<kind>.<group>/<name>`, as kubectl. |
| Errors | kubectl wording for common errors (`Error from server (NotFound): pods "x" not found`, `error: the server doesn't have a resource type "x"`), followed where useful by a KubeDojo hint line marked with `ⓘ`. |

## 5. Limits (per lab, configurable)

| Limit | Default | Error |
| --- | --- | --- |
| Resources per lab (excluding Events) | 100 | `VALIDATION_FAILED: lab resource limit (100) reached` |
| Events retained per lab | 500 (oldest dropped) | — |
| Command input size | 16 KiB | `VALIDATION_FAILED` |
| Virtual file size | 64 KiB | `VALIDATION_FAILED` |
| Virtual files per lab | 20 | `VALIDATION_FAILED` |
| Pods created by one command (via scale/replicas) | 50 | `VALIDATION_FAILED` |
| Command rate | 100 per minute per user (Redis rate limit, not a lab budget) | `RATE_LIMITED` |
